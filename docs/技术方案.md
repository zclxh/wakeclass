# WakeClass 课程表导入 App · 技术方案

> 版本：v0.2　|　目标平台：Flutter（Android / iOS，兼容 Windows/macOS 桌面调试与 Web）
> 与仓库中已有的 Web/PWA 版 `wakeclass` 同品牌，共享课表文本格式经验，但技术栈与导入路线独立。

---

## 1. 项目定位

一个**手机优先的大学课程表 App**，核心能力是：

1. **截图导入**：用户对教务系统课表页截图 → App 端 OCR 识别 → 自动还原为结构化课程数据（课程名、教师、周次、节次、地点）。
2. **好用的课表**：周视图网格、周次切换、今日/当前课程定位、冲突检测。
3. **可扩展导入**：架构预留「教务系统直连」适配层接口，后续可平滑接入强智/正方等系统（复用 `wakeclass` Web 版的适配经验）。

> **目标教务系统（实测）**：
> - 强智科技（jsxsd）：标准网格课表页（12 行节次 + 星期表头 + rowspan 合并），v0.2 已实现直连；
> - 沈阳建筑大学：**金智 CAS 统一认证（`authserver`）+ URP 教务（`eams`）**，v0.2 已实现直连
>   （密码按官方 encrypt.js 规则 AES-CBC 加密、票据跳转、URP 课表页定位、GBK 自适应解码）；
> - 新版正方（`jwglxt`）等同构课表页由同一解析器兼容，直连适配器后续接入。
> 解析器与测试夹具按上述真实形态定制。

### MVP 范围（本期交付）

- 相册选图 / 拍照 → 文字识别（ML Kit 端上 OCR）
- 网格解析：表头（星期列）→ 节次行 → 文本块 → 单元格 → 课程字段
- 识别结果**预览与校对**（增删改课程、修正字段、查看告警）
- 周课表网格展示（周切换、课程配色、冲突提示）
- 本地持久化（JSON，换学期/换设备备份待后续）
- 内置「演示导入」模式（无需真机 OCR 即可完整体验流程）

### 非目标（本期不做）

- 教务系统账号直连登录（架构预留，后续接入）
- 多学期并存、系统级课前推送、云同步、分享长图
- 账号体系 / 服务端

## 3. 截图 OCR 导入方案（核心）

### 3.1 导入流水线

```
选图(相册/拍照)
  → 预处理（可选：放大、灰度，交由引擎处理）
  → OCR（输出带坐标的文本块 OcrTextBlock[]）
  → GridParser：推断网格 → 块分配 → 单元格聚合
  → CellTextParser：逐格解析课程字段（名称/教师/周次/地点）
  → 生成 Course[] + 告警列表
  → 校对页（人工确认/修改）
  → 写入 ScheduleStore
```

### 3.2 OCR 引擎选型

| 方案 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| Google ML Kit 文字识别（端上） | 免费、离线、隐私好、中文支持、返回**带坐标的文本行** | 表格线不可用时准确率依赖图片清晰度 | **默认引擎** |
| 百度/腾讯/阿里云 OCR（表格识别） | 中文表格场景更强，可返回单元格结构 | 需 API Key、联网、有费用、隐私 | 接口抽象预留，后续作为可选引擎 |
| 端上 PaddleOCR（自部署） | 开源可定制 | 包体大、集成成本高 | 后续评估 |

**关键抽象**：`OcrEngine` 只约定「图片字节 → 带边界框的文本块列表」，识别细节与引擎解耦；`MockOcrEngine` 返回内置模拟识别结果，保证开发机（Windows 桌面）也能跑通全流程。

```dart
abstract class OcrEngine {
  String get name;
  Future<List<OcrTextBlock>> recognize(Uint8List imageBytes);
}
```

坐标统一用**相对坐标（0..1）**，与图片分辨率解耦。

### 3.3 网格解析算法（GridParser）

这是截图导入的核心。输入是 OCR 文本块列表（每块：文本 + 边界框），输出课程列表。

#### 第 1 步：文本块分类

| 类别 | 判定规则（正则） | 用途 |
|---|---|---|
| 表头块 | `星期[一二三四五六日天]` / `周[一二三四五六日天]`（不含「节」） | 确定列边界、星期编号 |
| 节次块 | `第?(\d+)(-|—|至)(\d+)节` / `第?\d+节` / 纯数字 1-12 | 确定行边界、节次区间 |
| 段标题块 | `上午/下午/晚上/中午/早晨/第一大节…` | 过滤（不参与网格） |
| 正文块 | 其余落入表体内的块 | 课程内容 |

#### 第 2 步：列布局推断

- 表头块按 x 排序 → 依次对应星期 1..n；
- 列边界 = 相邻表头中心 x 的中点；最左/最右列向两侧外扩；
- 表头缺失（截图裁掉了表头行）→ 生成告警「未检测到星期表头」，退化为按正文块 x 聚类（后续版本增强）。

#### 第 3 步：行布局推断

- 节次块按 y 排序，解析每行的 `[startPeriod, endPeriod]`：
  - `第1节`…`第12节` → 12 个单节次网格行；
  - `第1-2节`、`第3-4节`… → 6 个双节次网格行（行高即 2 节课）；
  - 两种形态都能得到「网格行 → 节次区间」映射；
- 行边界 = 相邻节次块中心 y 的中点；
- **合并单元格检测**：若某正文块的纵向范围跨越了 2 个以上网格行（重叠比例超阈值），判定为 rowspan，该课程节次区间取跨越范围（对应教务系统 rowspan=2 的单元格，OCR 通常只给出一块居中文本）。

#### 第 4 步：文本块分配

对每个正文块：

- 横向：取与各列水平重叠最大的列（优先用中心点落在列内）；
- 纵向：取纵向重叠超过阈值（默认 30%）的网格行范围；
- 同一（天, 节次）单元格内的多个块 → 按 (top, left) 排序聚合。

#### 第 5 步：单元格文本 → 课程字段（CellTextParser）

单元格文本按行分析，识别四类字段：

| 字段 | 判定规则 | 示例 |
|---|---|---|
| 周次 | 周次表达式（含 `-`/`,`/`单`/`双`），见 §3.4 | `1-16周`、`3-15周(单)` |
| 地点 | 含 `楼/室/场/馆/区/教` 或以 2-3 位数字结尾 | `教一101`、`计算机楼205` |
| 教师 | 无数字、长度 ≤ 4 的非首行 | `张明远` |
| 课程名 | 第一个非周次/地点/节次的正文行 | `高等数学A` |

一个单元格可能含**多门课**（不同周次分上下段，或 `<hr>` 分隔）→ 按周次行分段拆分为多条课程记录。

#### 第 6 步：结果与告警

生成 `GridParseResult { courses, rawCells, warnings }`：

- 每格解析成功的课程 + 置信度/告警（如「周次未识别，已默认全学期」）；
- 未分配进任何网格的正文块 → 进入告警列表，在校对页展示原始文本供手动添加；
- 冲突检测（同一天同一节次两门课）→ 告警提示。

### 3.4 周次表达式解析（WeekParser）

从 Web 版移植并强化，支持：

| 输入 | 解析结果 |
|---|---|
| `1-16周` | 1..16 |
| `3-15周(单)` / `单周` | 3,5,…,15 |
| `2-16周(双)` / `双周` | 2,4,…,16 |
| `1-8,10-16周` | 1..8 ∪ 10..16 |
| `第3周` | {3} |
| `全周/每周/全学期` | 1..学期总周数 |
| 纯数字列表 `1 2 3` | {1,2,3} |
| 空 | 告警 + 默认全学期 |

### 3.5 与「教务系统直连」的关系（v0.2 已实现强智直连）

导入层定义统一抽象，两条路线产出**同一数据模型**（`ImportPreview`），
UI（校对页）与存储层无需感知差异：

- **截图路线**（v0.1）：图片 → OCR → GridParser → `ImportPreview`；
- **直连路线 A（v0.2，强智 jsxsd）**：`QzJwxtClient` 在 App 内完成
  登录页探测（表单/验证码识别）→ 登录（验证码人工输入，不绕过）
  → 课表页（`xskb/xskb_list.do`，双入口容错）→ 学期选择（`xnxq01id`）
  → `ScheduleTableParser` 解析课表 HTML（rowspan/colspan 合并、一格多课）
  → 同一 `ImportPreview` → 同一校对页；
- **直连路线 B（v0.2，金智 CAS + URP，真实系统实测通过）**：`CasUrpClient` 完成
  登录页探测（`execution` / `pwdEncryptSalt` / `lt`）→ 密码按 encrypt.js
  规则加密（AES-CBC + 64 字节随机前缀吸收未知 IV，pointycastle 实现，含 Node
  crypto 参考向量测试）→ 登录（验证码按需人工输入，`getCaptcha.htl`）
  → 跟随 302 票据跳转合并 Cookie（**jsessionid URL 重写**：先访问 eams 取得
  权威 service，后续请求全部注入 jsessionid）→ URP 课表壳页（`courseTableForStd.action`）
  提取学期/学籍 id → POST `courseTableForStd!courseTable.action` → 解析页面内嵌
  **TaskActivity 数据**（星期×节次索引 + 53 位周次掩码 → 含单双周的周次集合，
  已与页面「实验安排」明细表交叉验证一致）；编码按中文词命中数在
  UTF-8 / GBK / 双重编码还原三者间自动选择；
- 强智流程移植自 Web 版 `wakeclass/lib/importers.mjs` 的 `qz()` 适配器，
  两套直连均用本地模拟教务系统做端到端测试（`wakeclass/test/mock-jwxt.mjs`
  与 `app/test/mock_cas_urp.cjs`），CAS+URP 另用真实账号实测（29 门课程）；
- 适配层接口（`JwxtLoginChallenge` / `CasLoginChallenge` / `JwxtImportResult`）
  已为正方（`jwglxt`）等系统预留扩展点。

## 4. 数据模型

```dart
class Course {
  final String id;          // 随机 UUID
  String name;              // 课程名
  String teacher;           // 教师（可空）
  String location;          // 地点（可空）
  List<int> weeks;          // 1 起始、升序去重
  int dayOfWeek;            // 1..7（周一=1）
  int startPeriod;          // 起始节次，1 起始
  int endPeriod;            // 结束节次（含）
  String note;              // 备注（可空）
  int colorIndex;           // 配色索引（按课程名哈希稳定分配）
  String source;            // 'ocr' | 'manual' | 'mock' | 'jwxt'
}

class Schedule {
  String id;
  String title;             // 如「2026-2027学年第一学期」
  DateTime termStart;       // 第 1 周周一的日期（驱动周次计算）
  int totalWeeks;           // 学期总周数（默认 20）
  List<Course> courses;
}
```

当前周计算：`currentWeek = ((today - termStart).inDays / 7).floor() + 1`，超出 [1, totalWeeks] 时钳制。

JSON 序列化规则固定字段名（snake_case），向后兼容加字段不删字段。

## 5. 存储设计

MVP 用 `shared_preferences` 存一个 `schedule.json`（单课表）：

- 课程量级（单学期约 10-40 门）远小于 JSON 文件的性能瓶颈；
- 无原生 SQL 依赖，Android/iOS/桌面全平台一致；
- 数据结构已为后续 `sqflite` 迁移预留（id、时间戳字段齐全）。

后续版本（多学期/多课表）升级为 `sqflite` 或 `drift`，迁移时直接由 JSON 导入。

## 9. 风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| OCR 表格线依赖 | 部分教务课表无边框线、文本跨格 | 块分配按重叠率而非表格线；提供手绘网格辅助（后续） |
| 单双周/多课程同格 | 复杂单元格易误拆 | 校对页人工兜底；解析规则持续从真实样例回归 |
| 节次行识别失败 | 截图缺左侧节次列 | 告警 + 人工指定每格节次（校对页兜底） |
| 教务系统验证码 | 直连登录的普遍障碍 | 直连支持验证码图片人工输入（不绕过、不破解）；滑块/扫码/短信码等改用截图导入 |
| 平台差异 | ML Kit 在 Windows 桌面不可用 | MockOcrEngine 演示模式 + Android/iOS 真机 |
| 单双周显示 | 非本周课程需正确淡显 | 周次计算集中于 core，UI 只消费结果 |
| 页面编码 | 教务页面编码不一 | UTF-8 / GBK 自适应解码，其余编码提示改用截图导入 |
